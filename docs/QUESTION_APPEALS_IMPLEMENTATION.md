# Question appeals — implementation and operations (9 Nov 2026)

Branch: `feature/question-appeals-v2-20261109`.

Source of functional rules: `AI_Quiz_Game_Appeals_Requirements_2026-11-09.md`
supplied by the project owner. **Do not treat this note as permission to change the
approved economy, merge the branch, or deploy paid model requests.**

## Components

- `backend/persistence/appeal_policy.py`: pure complaint rules, monthly
  escalating nonrefundable bronze fee, deposit boundaries and moderation.
- `backend/persistence/appeal_routes.py`: authenticated quote, submit and
  paginated user-only history; also a lost-question recovery endpoint for F5.
  There is **no public route** to issue a verdict or credit a wallet.
- `backend/persistence/appeal_service.py`: quote, atomic filing,
  idempotent settlement, question quarantine and permanent blocking.
- `backend/persistence/appeal_ai_security.py`: bounded Pydantic contracts,
  untrusted evidence isolation, anti-prompt-injection and exact JSON parsing.
- `backend/persistence/appeal_worker.py`: separate Keddy and Judge API calls,
  bounded retries, content-inconclusive player-favoring policy and
  seven-day technical-expiry refund.
- `backend/migrations/versions/0010_question_appeals.py`: durable appeal and
  moderation records; `0011_appeal_question_expenses.py`: per-attempt expenses.
- `frontend/src/app/app.component.ts` / `.html`: SweetAlert complaint form
  on a currently active question or a losing question, plus manual-only
  **My Complaints** inside the profile menu.

All question texts and answers are frozen in the original-language appeal
snapshot with four A/B/C/D options. Hidden options are separately identified;
the right answer is never returned through appeals APIs. An upheld
**pre-answer** appeal replaces the removed question with another of the same
number and difficulty without an extra star. An upheld **post-loss** appeal
never edits the lost run; only the agreed ledger compensation is made.

The Judge uses the stored `Question.generator_model` to prohibit reviewing
a question generated by the same model. Its explanatory texts are stored in
English and the complaint's original language; history never runs translation.

## Migration and local startup

Run migrations **before** restarting the app:

```powershell
git switch feature/question-appeals-v2-20261109
git pull origin feature/question-appeals-v2-20261109
cd backend
python -m alembic upgrade head
python -m unittest discover -s tests -v
python -m uvicorn api:app --reload --host 127.0.0.1 --port 8000
```

For durable scheduled processing, start a **separate terminal or service**
from the `backend` directory with:

```powershell
python -m persistence.appeal_worker --loop
```

One-shot for an external scheduler: `python -m persistence.appeal_worker --once`.
The HTTP submission schedules immediate best-effort handling, but is **not**
a replacement for this dedicated worker. Never run `--loop` with the
reloading web server's process.

Frontend is still Angular and runs separately in VS Code:
`cd frontend; npm install; npm start`.

## Regression verification

The `Appeals security and policy` GitHub Actions workflow covers:

1. Existing appeal policy and malicious-text / strict-JSON tests.
2. Entire Python backend unittest discovery suite.
3. Angular tests and production build.
4. Alembic migrations on a disposable PostgreSQL service.
5. **Real PostgreSQL filing and settlement**: pre-answer quarantine, stable
   idempotency key, non-duplicated refunds, Q16 independent gold wager
   and platinum compensation, and technical-expiry deposit return.

A full browser E2E with a running local database/backend and real paid Keddy
and Judge responses is a separate release gate; the CI suite is offline
and cannot certify real-model accuracy or deployed-model authorization.

## Financial and factual safety constraints

- Explicit consent plus the matching fee quote before any non-refundable
  debit. First five monthly cases have no filing fee, but still charge a
  one-star deposit.
- Never credit from AI-proposed amounts: the Judge returns a verdict only.
  An idempotent PostgreSQL ledger applies the server-side policy.
- **Q16** gold wager, gold appeal deposit, and optional bronze filing fee
  are three independent wallet operations.
- Exact bronze hint prices are captured on the question attempt from this
  migration forward. Historic spending predating receipt capture cannot be
  safely reconstructed by guessing.
- Refunding a wholly unused Platinum Helper marks the purchase refunded and
  disables further consultations; an on-question used helper receives at
  most one additional gold credit per purchase. No purchase may be refunded
  and compensated twice.
- **Needs policy confirmation**: the restored owner requirements expressly
  noted ambiguity in the precise helper-compensation interaction. Current
  implementation conservatively counts completed helper use on the disputed
  question and guards against any second credit. Do not silently broaden
  payouts to uses on unrelated questions.
- If the Judge cannot decide **on the merits**, it returns
  `inconclusive` and the case is upheld according to the approved policy.
  A timeout/technical failure is **not** upheld: up to three immediate
  retries, then daily retry; a seven-day unresolved case closes with a
  deposit refund only.
- The AI prompts do not fetch player-supplied links or independently browse
  public sources. Links are untrusted evidence. A separate verified factual
  source tool can be added later, but **do not label an LLM-only judgment as
  independently web-fact-checked**.
