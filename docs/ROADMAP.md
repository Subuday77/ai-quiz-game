# AI Quiz Game — требования и дорожная карта

> Рабочий документ от 18.10.2026. Решения принимаем и проверяем поэтапно.
> Ветка master не изменяется до проверки и слияния.

## Цель

Превратить существующую консольную Python-викторину в многоязычное
веб-приложение с персональными аккаунтами, игровой экономикой и AI-генерацией
вопросов. Продолжаем в репозитории Subuday77/ai-quiz-game.

## Архитектурные принципы

- Один репозиторий, отдельно Angular frontend и FastAPI backend.
- В разработке Angular и API запускаются независимо. В production Angular
  собирается в статические файлы; их раздаёт FastAPI.
- Правильный ответ остаётся на сервере. Клиент получает текст, варианты и ID
  вопроса; проверка ответа и награды выполняются на backend.
- Модель вызывается для генерации вопроса, а не для повторной проверки ответа.
- Игровые правила не зависят от интерфейса, БД и конкретного AI-провайдера.
- Каждый существенный шаг сопровождаем объяснением архитектуры и тестами.

## Игровые правила (принято)

- 15 основных вопросов: уровни сложности 0–14 по возрастанию.
- За 5, 10 и 15 правильных ответов в одной игре выдаются бронзовая,
  серебряная и золотая звёзды соответственно.
- Неправильный ответ на основном этапе прекращает игру.
- После 15 правильных ответов без использования игровых подсказок открывается
  секретный 16-й вопрос (сложность 15).
- На секретном вопросе подсказки недоступны. За правильный ответ предусмотрена
  платиновая звезда. Ошибка не отменяет уже заработанную золотую.
- Считаем использование помощи, а не наличие купленных подсказок.
  Смена категории или замена вопроса — помощь, косметическая тема — нет.
- В текущей консольной игре подсказок пока нет, поэтому бонус автоматически
  открывается после 15 правильных ответов. В игровом ядре счётчик уже есть.

## Планируемые функции (частично требуют решения)

1. Frontend: Angular, адаптивный UI, выбор языка, вопросы/ответы, профиль, темы.
2. Пользователи и PostgreSQL: регистрация, безопасная авторизация, история.
   Отображаемые имена могут совпадать; способ входа проектируется отдельно.
   Пароли нельзя шифровать с публичным именем в качестве ключа.
3. AI: несколько провайдеров, JSON Schema, Pydantic, retries с лимитом,
   нормализация причины остановки и обработка ошибок.
4. Качество и уникальность вопросов: теги, общая база, персональная история,
   проверка похожести и отдельная смысловая валидация перед показом игроку.
   Не допускать тривиальных, тавтологических, неоднозначных и фактически
   ошибочных вопросов; проверять соответствие заявленной сложности.
   Теги сами по себе не гарантируют уникальности.
5. Экономика: накопительные достижения и отдельный расходуемый баланс,
   обмен звёзд и магазин подсказок. Курс 10:1 — пока гипотеза.
6. Локализация: выбор из списка. Вопросы генерируются на выбранном языке.
   Переводы UI через AI Localizer кешируются глобально на язык; в профиле
   хранится предпочтение. Предусмотреть обновления словаря и RTL.
7. Монетизация: донаты, затем возможные реклама и rewarded ads после
   проверки требований платформ и фактических затрат.
8. Персонализация: цветовые темы и косметические награды.

## Этап 4 — качество вопросов и уникальность (запланировано)

Помимо проверки JSON Schema/Pydantic (структура ответа) требуется **семантическая
валидация** каждого сгенерированного вопроса до отправки игроку.

Антипримеры, которые должны отклоняться:
- «Какой материал используется для остекления окон?» — банальный вопрос,
  несоответствующий содержательной викторине и особенно высоким уровням.
- «Кто открыл второй закон Ньютона?» — тавтология/подсказка в самой
  формулировке, ответ практически очевиден из названия.

Требования к проверке:
- Вопрос действительно проверяет знания и не содержит прямого ответа или
  очевидной подсказки в формулировке.
- Фактическая корректность вопроса и отмеченного правильного ответа;
  недопустимы выдуманные предпосылки.
- Единственный обоснованный правильный вариант: без неоднозначности,
  дублирующихся или заведомо абсурдных отвлекающих ответов.
- Соответствие сложности текущему уровню 0–15, а не только числовому
  полю difficulty в JSON; избегать примитивных вопросов на старших уровнях.
- Грамотная формулировка, понятность на выбранном языке, отсутствие
  некорректных или неестественных переводов.
- Проверка на повторы и близкие по смыслу вопросы по общей базе и
  персональной истории (в дополнение к тегам).

Подход предстоит спроектировать: сначала улучшить промпт генератора и
добавить быстрые детерминированные фильтры, затем оценить независимую
LLM-проверку по чёткой рубрике (включая цену и задержку). При провале
качества — ограниченное число повторных генераций с диагностикой причины,
а при исчерпании лимита — корректная ошибка, **не показ плохого вопроса**.
Предусмотреть тестовый набор хороших и плохих примеров, включая оба выше;
ложные отклонения качественных вопросов тоже нужно измерять.

**Важно:** текущая проверка Pydantic гарантирует только корректный формат;
семантический контроль пока НЕ реализован.

### Промежуточная реализация (24.10.2026, feature-ветка)

- Генератор v1 остаётся исходным; экспериментальный v2 не включён.
- Локальная проверка точного буквального раскрытия ответа теперь работает
  независимо от режима AI-критика и может запросить повторную генерацию
  в пределах существующего лимита (AI_LOCAL_LEAK_MODE=enforce по умолчанию).
- Независимое определение всех правильных вариантов без передачи
  генераторского ключа реализовано пока как **тестовый инструмент**.
  Его результат не блокирует публикацию до живой калибровки.
- Формат вопроса в JSON и правила выдачи наград не изменены.
- PostgreSQL, жалобы игроков, постоянная статистика и тема-теги ещё
  **не реализованы**; модель данных и проверки описаны в
  docs/ANSWER_VALIDITY_EXPERIMENT.md и GitHub Issues #3, #4, #6.
- Смысловые теги описывают содержание вопроса, но **запрошенная и
  фактически наблюдаемая сложность не являются тегами**:
  семантически похожий вопрос может встретиться на соседнем уровне.

## Этап 0 — текущая реализация

- game_logic.py: независимое состояние игры, уровни, достижения, секретный
  16-й вопрос без зависимости от консоли или LLM.
- question_generator.py: исходный вызов модели выделен из main.py.
- main.py: консольный интерфейс, использующий игровое ядро.
- tests/test_game_logic.py: проверки уровней, 15+1, подсказок и сохранения
  золотой звезды при неверном ответе на бонусном вопросе.

Запуск тестов: python -m unittest discover -s tests -v

**Важно:** на этапе 0 ещё нет API, БД, UI, подсказок и настоящего начисления
валюты. Генератор пока использует json.loads без строгой JSON-схемы — это
будет исправлено на этапе 1. Награды в CLI пока выводятся, но не сохраняются.

## Как учимся

валидируемые ответы, ошибки провайдера, Tenacity, max retries, тестирование.
